# Расписание фоновых задач

## Что запускается

| Путь | Что делает | Как часто нужно |
|---|---|---|
| `/api/cron/hourly` | дневные советы + вечерние сводки челленджей + напоминание при пустом дне | чем чаще, тем точнее по времени |
| `/api/cron/daily` | месячные отчёты (Pro) + деактивация истёкших подписок | раз в сутки достаточно |

## Сейчас в `vercel.json` — две задачи

Это минимум, который проходит на любом тарифе Vercel, включая Hobby с лимитом
в две cron-задачи раз в сутки. `/api/cron/hourly` стоит на 18:00 UTC (21:00 МСК):
к этому часу у большинства пользователей уже прошло и время совета, и вечер для
сводки челленджа.

**Код рассчитан на редкий запуск и ничего не теряет:**

- совет уходит за сегодня, если время пользователя уже прошло, иначе — за вчера,
  если за вчера его ещё не было. За один тик — максимум один совет, поэтому при
  любой частоте человек получает его раз в сутки;
- сводка челленджа подводит последний *завершённый* день (сегодняшний, если
  вечер наступил, иначе вчерашний) и молча закрывает предыдущий пропущенный,
  чтобы в календаре не оставалось дыр;
- повторные запуски безопасны: дубли исключают уникальные ключи `DailyAdvice`
  и `ChallengeDay`.

Плата за редкий запуск — точность: человек с `adviceTime` 08:00 получит совет
в 21:00 МСК, а не утром.

## Как сделать точнее

Если тариф разрешает больше задач, замените блок `crons` в `vercel.json` на 24
записи — по одной на каждый час:

```json
"crons": [
  { "path": "/api/cron/hourly", "schedule": "0 0 * * *" },
  { "path": "/api/cron/hourly", "schedule": "0 1 * * *" },
  ...
  { "path": "/api/cron/hourly", "schedule": "0 23 * * *" },
  { "path": "/api/cron/daily",  "schedule": "0 8 * * *" }
]
```

Менять в коде ничего не нужно: тик сам отсеивает тех, чьё время ещё не пришло.

## Вариант без Vercel

Любой внешний планировщик — VPS, cron-job.org — дергает тот же адрес:

```
curl -H "Authorization: Bearer $CRON_SECRET" https://<домен>/api/cron/hourly
```

Строка для crontab на VPS, каждый час:

```
0 * * * * curl -fsS -H "Authorization: Bearer СЕКРЕТ" https://<домен>/api/cron/hourly >/dev/null
```

`CRON_SECRET` обязателен: без него эндпоинт открыт всему интернету, и любой
желающий запускает рассылку за ваш счёт.

## Ограничение по времени

Функция Vercel живёт 60 секунд. `/api/cron/hourly` делит их между тиками: 28
секунд на советы, 18 на челленджи, 8 на вечерние напоминания «сегодня в
дневнике пусто» (`cron/reminders.ts`; напоминание уходит только в окно 17:00–23:59
локального времени, поэтому запуск в 18:00 UTC покрывает Москву). Кого не
успели — получат на следующем запуске, это штатное поведение, в логах остаётся
предупреждение `out of time, rest continues next tick`.

## Supabase на бесплатном тарифе

Проект засыпает после недели без обращений. Ежедневный крон обращается к базе и
тем самым не даёт ему уснуть — отдельно ничего настраивать не нужно.

## Почему в `vercel.json` есть `ignoreCommand`

В настройках проекта Vercel включён **Ignored Build Step** — он отменяет сборку
и для превью, и для production (в статусе коммита видно
`Canceled by Ignored Build Step`). Настройки `vercel.json` имеют приоритет над
проектными, поэтому `"ignoreCommand": "exit 1"` возвращает автосборку.

Семантика обратная интуиции: **код возврата 0 — пропустить сборку, 1 — собирать.**
Чтобы снова отключить автодеплой, поставьте `"exit 0"`, уберите строку или
настройте в дашборде.
