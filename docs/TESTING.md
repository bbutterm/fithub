# Тесты

Что проверяется, чем и как это запустить.

## Три набора

| Набор | Команда | Нужна база | Сколько |
|---|---|---|---|
| Юнит, сервер | `pnpm --filter bot-api test` | нет | 116 |
| Юнит, Mini App | `pnpm --filter webapp test` | нет | 16 |
| Интеграционные | `pnpm test:integration` | да | 112 |

`pnpm test` запускает оба юнит-набора. В CI после них идут интеграционные на
сервисном PostgreSQL, сборка Mini App и накат миграций на чистую базу.

## Принцип

На каждую область — несколько случаев: обычный, отказ и граница. Тест, который
повторяет реализацию строчка в строчку, не пишем: он ломается при каждой
правке и ничего не ловит.

Разделение между наборами простое. Если правило можно проверить без базы, оно
живёт в чистом модуле и проверяется юнит-тестом. Всё остальное — поведение
маршрута, обработчика бота или тика расписания — проверяется интеграционным
тестом на настоящей базе, с подменой Telegram и моделей.

## Что покрыто интеграционными

| Файл | Область |
|---|---|
| `api-core` | Вход по initData, доступ к чужим данным, валидация профиля, дневник, фото-прокси |
| `api-features` | Блюда, челленджи, админские права, аналитика, крон, удаление аккаунта |
| `bot-flows` | Фото, голос, уточнение ответом, кнопки под карточкой, исчерпанный лимит, удаление |
| `retention` | Режим «можно?», вечернее напоминание, «ел как обычно» |
| `feed` | Публикация, очередь свайпов, голоса, жалобы, недельный лидерборд |
| `limits-subscription` | Дневной лимит, возврат попытки, анти-спам, блокировки, подписка |
| `cron-timezones` | Сутки по поясу человека, советы, месячный отчёт |
| `provider-failures` | Отказ модели: текст человеку, возврат попытки, снятие блокировки |

## Запуск интеграционных локально

Нужен PostgreSQL. Через Docker:

```bash
docker run -d --name fithub-test -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=fithub_test -p 5433:5432 postgres:17

export TEST_DATABASE_URL="postgresql://postgres:postgres@localhost:5433/fithub_test"
DATABASE_URL="$TEST_DATABASE_URL" DIRECT_URL="$TEST_DATABASE_URL" \
  pnpm --filter bot-api exec prisma migrate deploy

pnpm test:integration
```

Переменная называется `TEST_DATABASE_URL`, а не `DATABASE_URL`, намеренно:
случайный запуск не должен очистить рабочую базу. Перед каждым тестом все
таблицы очищаются, нумерация id при этом не сбрасывается — в боте есть
счётчики в памяти процесса, привязанные к id пользователя.

## Чего эти тесты не проверяют

- **Качество распознавания.** Все вызовы моделей подменены. Насколько точно
  модель считает калории, тестами не измеряется: для этого нужен размеченный
  набор фото и отдельный прогон.
- **Внешний вид Mini App.** Проверяется только чистая логика. Для экранов есть
  скриншотный скрипт `scripts/ui-smoke.py` на мок-данных, в CI он не ходит.
- **Настоящие деньги и настоящий Telegram.** Платёж Stars не совершался, бот в
  тестах отвечает подменённым Bot API.
- **Нагрузка.** Параллельность проверяется логикой (блокировки, атомарные
  счётчики), а не прогоном под нагрузкой.

## Полезное при написании нового теста

- Помощники в `src/__tests__/integration/helpers.ts`: подписанная initData,
  вход через настоящий маршрут, создание профиля и приёма пищи, перехват
  вызовов Bot API, сборка апдейтов Telegram.
- Вызовы моделей подменяются через `vi.mock` на `ai/food.js`, `ai/dietCheck.js`
  или `lib/ai.js` — смотря что проверяется.
- Время: дату не зашивать. Лидерборд считает текущую неделю, а «обычный день» —
  последние две недели по системным часам; тест с календарной датой проживёт
  неделю. Отсчитывайте от `new Date()`.

## Качество моделей: отдельный контур

Тесты подменяют вызовы моделей, поэтому точность распознавания они не
измеряют принципиально. Для неё есть eval — отдельный набор команд в
`apps/bot-api/eval/`, который ходит в настоящие модели за настоящие деньги и
потому в CI на каждый пуш не гоняется.

| Что | Команда | Когда |
|---|---|---|
| Прогон по эталонному набору | `pnpm --filter bot-api eval run` | при выборе модели |
| Метрики, пороги, страница сравнения | `pnpm --filter bot-api eval score` | после прогона |
| Значимость, цена, вес против состава | `pnpm --filter bot-api eval analyze` | после score |
| Прогон по своим фотографиям | `pnpm --filter bot-api eval inbox` | перед выкаткой новой модели |

Итоги прошлых прогонов лежат в `eval/results/`, сырые вызовы — в `eval/runs/`
и не версионируются.

**Проверка на своих снимках обязательна перед сменой модели в проде.**
Эталонный набор снят в студии сверху при ровном свете; телефонные снимки
живого пользователя выглядят иначе. Для этого есть пайплайн: кладёте
фотографии в `apps/bot-api/eval/inbox/`, пушите, и workflow «Eval по своим
фото» прогоняет их и присылает отчёт комментарием к коммиту. Подробности и
формат необязательного `labels.csv` — в `eval/inbox/README.md`. Нужен секрет
репозитория `OPENROUTER_API_KEY`.

Без эталона отчёт считает не точность, а согласие моделей между собой. Это
разные вещи: на плотной еде со скрытым жиром занижает весь набор сразу, и
общее мнение оказывается таким же неверным, как каждый ответ по отдельности.
